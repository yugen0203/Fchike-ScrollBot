# 株式会社Rion Lab Japan コーポレートサイト リニューアル 要件定義書

- 文書バージョン: 1.0
- 作成日: 2026-06-02
- 対象: rion-lab-japan.com フルリニューアル

---

## 1. 背景・目的

現行サイトは WordPress で運用されているが、以下の課題がある。

- ページ表示が重くなりがち（プラグイン依存・DB負荷）
- WordPress 本体／プラグインのアップデート・脆弱性対応の運用負荷
- デザインの陳腐化

本プロジェクトでは、**WordPress を廃止**し、

1. **軽量・高速**なフロントエンド（フレームワーク非依存の静的構成）
2. **ヘッドレスCMS（microCMS）** によるコンテンツ管理
3. **曜日替わりデザイン**（月〜金で完全に異なる5テーマ、土日は金曜を継続）
4. **PHP＋SQLite** による自前のお問い合わせフォーム＋管理画面

を実現する。画像・アイコン・レイアウトはすべて現行から刷新する。

## 2. スコープ

### 2.1 対象範囲（In Scope）

- トップ / 会社情報 / サービス / お問い合わせ の各ページ
- 曜日替わりデザインシステム（5テーマ）
- microCMS 連携（お知らせ・実績などの動的コンテンツ）
- お問い合わせフォーム（PHP）＋ 管理画面（一覧・詳細・CSV出力・削除）
- レスポンシブ対応（スマホ／タブレット／PC）
- 基本的なSEO・OGP・アクセシビリティ対応

### 2.2 対象外（Out of Scope）

- DX研修ラボ（dx-lab.rion-lab-japan.com）の改修 ※リンク連携のみ
- 多言語化（将来拡張として設計上は考慮）
- 決済・会員機能

## 3. 採用技術・構成の選定

### 3.1 ヘッドレスCMS：microCMS（採用）

| 観点 | 評価 |
|---|---|
| 料金 | 無料（Hobby）プランあり。API/メンバー/コンテンツ数の制限内で無償継続可 |
| 日本語 | 管理画面・ドキュメント・サポートが日本語 |
| 軽量性 | コンテンツはJSON APIで配信。フロントは静的のまま保てる |
| 長期運用 | 国産SaaSで実績多数。WordPressのような自前保守が不要 |

> 比較検討：Newt（国産・モダン）、Contentful（海外大手・管理画面が英語中心・料金改定リスク）、静的管理（無料・最軽量だが更新に編集作業が必要）。**日本語運用・無料・長期安定**の観点から microCMS を採用。

**APIキー保護**：microCMS の APIキーをブラウザに晒さないため、**Xサーバー上のPHPプロキシ（`api/cms.php`）経由**で取得する。これによりキーはサーバー側のみに保持され、簡易キャッシュも効かせられる。CMS未設定時はサイト内蔵の静的フォールバックデータで表示する。

### 3.2 フロントエンド：静的HTML + CSS + Vanilla JS

- ビルド不要・依存パッケージ最小。CDN/サーバー直置きで動作。
- フレームワークを使わないことでバンドルサイズ・初期表示を最小化（「重くしたくない」要件に直結）。
- アイコンは **Font Awesome**。画像は軽量SVG/CSSアート＋写真スロット。

### 3.3 サーバー：Xサーバー（PHP + SQLite）

- お問い合わせフォーム・管理画面は **PHP** で実装。
- DBは **SQLite**（ファイルベース）を採用。MySQLの初期設定が不要で、どのレンタルサーバーでも動作。問い合わせ件数規模では十分。
- 将来MySQLへ移行可能なよう、DBアクセスは `lib/db.php` に集約。

## 4. 曜日替わりデザイン要件

### 4.1 仕様

- 日本時間（JST）の曜日でテーマを自動切替。
- 月〜金は5つの**完全に異なるテーマ**、**土日は金曜テーマを継続**。
- テーマで変わる要素：配色（カラーパレット）／タイポグラフィ（書体・字間）／ヒーローのSVGビジュアル／装飾モチーフ／角丸・余白などの形状言語。
- 切替は `<html data-theme="...">` 属性＋CSS変数で実現。JSが曜日を判定して付与。
- ?theme=mon〜fri のクエリでプレビュー可能（確認・検証用）。

### 4.2 テーマ一覧

| 曜日 | テーマ名 | コンセプト | 主配色 | 形状言語 |
|---|---|---|---|---|
| 月 | Fresh Start | 週初め・クリーン・ミニマル | ブルー系 | 直線・シャープ |
| 火 | Momentum | 推進力・エネルギッシュ | コーラル/オレンジ | 斜め・動的 |
| 水 | Flow | 落ち着き・自然・流れ | ティール/グリーン | 曲線・波 |
| 木 | Trust | 信頼・上質・堅実 | ネイビー/ゴールド | グリッド・端正 |
| 金 | Spark | 創造・華やか（土日も継続） | パープル/マゼンタ | 幾何学・グラデ |

## 5. 機能要件

### 5.1 お問い合わせフォーム（`contact.html` → `api/contact.php`）

- 入力項目：お名前（必須）／会社名／メール（必須・形式チェック）／電話／種別（選択）／お問い合わせ内容（必須）／個人情報同意（必須）
- バリデーション：クライアント側＋**サーバー側（必須）**。
- セキュリティ：CSRFトークン、ハニーポット（スパム対策）、入力サニタイズ、レート制限（簡易）。
- 保存：SQLite に保存。
- 通知：管理者宛にメール送信（`mail()`／設定でSMTP拡張可）。送信失敗してもDB保存は担保。
- 完了：サンクス表示（または `?sent=1`）。

### 5.2 管理画面（`admin/`）

- ログイン認証（パスワード。`config.php` にハッシュ保存。セッション管理）。
- 問い合わせ一覧（日時・氏名・種別・メール・ステータス）。ページング／検索。
- 詳細表示。
- ステータス変更（未対応／対応中／完了）。
- CSVエクスポート（Excel対応・UTF-8 BOM）。
- 削除（確認付き）。
- 総当たり対策（ログイン試行の簡易制限）。

### 5.3 CMS連携（`api/cms.php` + `assets/js/cms.js`）

- お知らせ（news）一覧をトップに表示。
- 取得失敗時は内蔵フォールバックで必ず表示（サイトが壊れない）。

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| パフォーマンス | フレームワーク非依存。画像は遅延読込・SVG優先。Lighthouse Performance 90+ を目標 |
| レスポンシブ | 360px〜の主要幅で崩れないこと |
| アクセシビリティ | 適切な見出し階層、altテキスト、コントラスト比、キーボード操作 |
| SEO | title/meta description、OGP、構造化データ（Organization）、sitemap |
| セキュリティ | フォームのCSRF/スパム対策、管理画面の認証、APIキーのサーバー側保持 |
| 保守性 | テーマ・コンテンツ・DBアクセスを分離。設定は config に集約 |
| ブラウザ | 主要モダンブラウザ最新版 |

## 8. 受け入れ条件（抜粋）

- [ ] 月〜金でデザインが明確に切り替わり、土日は金曜表示になる
- [ ] CMS未設定でも全ページが正常表示される
- [ ] お問い合わせが送信でき、管理画面の一覧に反映される
- [ ] 管理画面はログインなしでアクセスできない
- [ ] スマホ／PCでレイアウトが崩れない
- [ ] WordPress 由来の依存が一切ない

## 9. 今後の検討事項

- 写真素材：本書時点では生成画像ツールが当環境で使用不可のため、SVG/CSSアートで構築。写真は `assets/img/` のスロットへ後日差し込み（手順は `assets/img/README.md`）。
- 正式な所在地・電話番号・代表メッセージ等は確定情報に差し替え（HTML内の `〔要確認〕` 箇所）。
- 多言語化・実績/ブログの拡充は microCMS のAPI追加で対応可能。
