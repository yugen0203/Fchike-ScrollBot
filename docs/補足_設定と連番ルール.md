# 補足資料：設定・連番ルール・安全運用（出品Bot / ListBot）

操作マニュアル（Windows用 / Mac用）の補足です。もう少し細かく設定したい人・仕組みを知りたい人向け。

---

## 1. 連番ルールをもっと細かく決めたい

GUIで足りない場合は、設定ファイル **`config_listbot.yml`** の `grouping:` を編集できます（保存場所は下記）。

```yaml
grouping:
  mode: together         # together=まとめて連番出品 / max_size=最大席数で分割
  max_group_size: 2      # max_size のとき1グループの最大席数
  remainder: single      # 端数: single=単独で出品 / merge=直前グループに足す
  partition_overrides: {}# 連番数ごとに割り方を指定（下記）
  single_as_bara_ok: true# 1席は「バラ売り可」で出品
```

### partition_overrides（連番数ごとに割り方を固定）
特定の連番数だけ、決まった割り方にしたいときに使います。合計が元の席数と一致すること。

```yaml
  partition_overrides:
    3: [2, 1]      # 3連番 → [2席][1席]
    4: [2, 2]      # 4連番 → [2席][2席]
    6: [2, 2, 2]   # 6連番 → 2席ずつ3グループ
    8: [4, 4]      # 8連番 → [4席][4席]
```

> overrides は最優先で適用され、無ければ `mode`/`max_group_size`/`remainder` の設定が使われます。

### 割り方のかんたん早見表（mode: max_size の例）

| 連番数 | 最大2・single | 最大2・merge | 最大4・single |
|---|---|---|---|
| 3 | [2][1] | [3] | [3] |
| 4 | [2][2] | [2][2] | [4] |
| 5 | [2][2][1] | [2][3] | [4][1] |
| 6 | [2][2][2] | [2][2][2] | [4][2] |
| 8 | [2][2][2][2] | [2][2][2][2] | [4][4] |

## 2. 価格について

- 出品価格は常に、その席で設定できる**範囲の最高額**（例 ¥3,600〜¥6,900 なら ¥6,900）。
- 席ごとに上限が違う場合は、**席ごとにその席の最高額**を入れます。
- この仕様は要件で固定です（`config_listbot.yml` の `listing.price_strategy: max`）。

---

## 3. 並行処理（複数日付を同時に）

- GUIの「複数日付を複数タブで同時出品」をオンにすると、対象日付を**同時に処理**して速くなります。
- 「最大タブ数」で同時に開く画面の数を決めます（既定5）。多すぎるとPCが重くなることがあります。
- ログインは最初の1回だけ（同じブラウザのログインを全タブで共有）。

`config_listbot.yml`：
```yaml
parallel: true
max_parallel_tabs: 5
```

## 4. 速度・待ち時間の調整

サイトの反応が遅い／速すぎて失敗する場合は `config_listbot.yml` で調整します。

```yaml
listing:
  between_actions_ms: 400   # 各操作の間の待ち時間(ミリ秒)。増やすと安定、減らすと高速
scroll:
  step_px: 600              # 1回のスクロール量
  wait_ms: 800              # スクロール後の待ち
  settle_ms: 1200           # 一番下に着いたあとの追加待ち（読み込み待ち）
  stable_rounds: 6          # 「これ以上伸びない」と判断する連続回数
```

## 5. 設定ファイル・データの保存場所

| 種類 | Windows | Mac |
|---|---|---|
| 設定ファイル | `%APPDATA%\ListBot\config_listbot.yml` | `~/Library/Application Support/ListBot/config_listbot.yml` |
| ログイン情報 | `%APPDATA%\ListBot\.env.listbot` | `~/Library/Application Support/ListBot/.env.listbot` |
| ログ | `%APPDATA%\ListBot\logs_listbot\` | `~/Library/Application Support/ListBot/logs_listbot\` |

> ScrollBot とは別の場所に保存されるので、2つのアプリは干渉しません。

## 6. 確認モード（誤出品の防止）

- **確認モードON**：最後の「出品する」ボタンの**直前で止まります**。内容を自分で確認して手で押せます。
- **確認モードOFF（フル自動）**：最後まで自動で出品が確定します。
- お試し・初めての日付・設定変更後は、**まず確認モードON**で1回試すのがおすすめです。

`config_listbot.yml`（GUIのチェックが優先されます）：
```yaml
listing:
  confirm_mode: false   # true で確認モード
```

---

## 7. サイトの見た目が変わって動かなくなったら（上級者向け）

Fチケ側のページ構造（HTML）が変わると、ボタンや入力欄を見つけられず止まることがあります。その場合は `config_listbot.yml` の `sites.fchike.listing:` のセレクタ（要素の指定）を直します。**プログラム本体の修正は不要**です。

最新の画面構造は次のコマンドで取得できます（開発環境）：
```
python -m listbot.main --capture --date 9/17
```
→ ログイン → スクロール → その試合の出品ページを開いて HTML/スクショを保存（出品はしません）。

## 8. 安全運用チェックリスト

- [ ] お試しは確認モードONで実施した
- [ ] フル自動で出した分は、必要ならキャンセルした
- [ ] ログインID・パスワードは他人に共有していない
- [ ] 出品後はメール／出品履歴で内容を確認した

## 9. 開発者向けメモ

- 開発実行：`python -m listbot.main`
- CLI：`--paths`（保存場所確認） / `--set-cred <ID> <PW>` / `--group 5,6,7,8 [--mode max_size --max 2]`（連番の割り方を確認） / `--capture [--date M/D]`
- 連番ロジックのテスト：`python -m listbot.test_grouping`
- ビルド：mac=`bash build/make_listbot_mac.sh` / Windows=GitHub Actions（`.github/workflows/windows-build.yml`）
